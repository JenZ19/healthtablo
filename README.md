# Семейный хаб здоровья

Локальное приложение, которое собирает медицинские документы всей семьи — людей и животных — и превращает их из груды PDF в связную картину: динамика каждого показателя по годам, что вне нормы прямо сейчас, что пора пересдать.

**Всё живёт на вашем компьютере.** SQLite и локальный веб-интерфейс, никаких облаков, аккаунтов и внешних запросов. Ни один байт медицинских данных никуда не уходит — это условие, а не особенность.

<sub>Интерфейс на русском, парсеры написаны под российские лаборатории.</sub>

## Никогда не программировали?

Есть подробная пошаговая инструкция, как собрать себе такой же хаб с помощью ИИ-помощника (Claude Code или Codex), не зная ни строчки кода: **[КАК-СДЕЛАТЬ-СВОЙ.md](КАК-СДЕЛАТЬ-СВОЙ.md)** — без единой команды в терминале.

Та же инструкция статьёй, с картинками: [как я собрала семейный хаб здоровья без программирования](https://submarineedu.ru/blog/hab-zdorovya-svoimi-rukami-bez-programmirovaniya).

## Что умеет

- **Разбирает бланки лабораторий** в структурированные данные: показатель, значение, единицы, референс. Из коробки — Гемотест, ИНВИТРО, СМ-Клиника, «Первый Доктор», Фемофлор, ЦГиЭ, ветеринарные Ветсоюз, ВЕТЛАБ и Inovalys, плюс живучий generic на всё незнакомое.
- **Читает сканы и фотографии** бумажных бланков — OCR через встроенный в macOS Vision, офлайн.
- **Строит график по каждому показателю** за все годы, с коридором референса.
- **Показывает, за чем следить**: что вне нормы, насколько именно (в процентах от границы), что ухудшается, что давно не пересдавали.
- **Ведёт животных наравне с людьми**: сроки вакцинаций и обработок, вес против породного коридора, календарь приёма лекарств, календарь состояния.
- **Менструальный календарь** для женских профилей: обильность, самочувствие, длина цикла и длительность считаются из отметок, ожидаемая дата — среднее по прошлым циклам.
- **Напоминает о сроках** пуш-уведомлениями: не отмечена сегодняшняя доза, подошёл срок обработки у животного, по прошлым циклам ожидается менструация. В самом уведомлении нет ни диагнозов, ни значений — его видно на заблокированном экране.
- **Цитирует рекомендации врача** из ваших же документов — дословно, со ссылкой на источник.

## Правила работы с медицинскими данными

Отдельный документ — **[RULES.md](RULES.md)**. Он выведен не из теории, а из ошибок, которые хаб уже совершал на настоящих анализах: смешанные единицы, слитые под одним маркером разные величины, дата рождения вместо даты забора. Каждая выглядела на графике правдоподобно.

Главное оттуда: **красивый график — не доказательство правильных данных.** Ошибка сопоставления рисуется так же гладко, как настоящая динамика.

## Чего не делает — намеренно

Хаб **не ставит диагнозов и не назначает лечение**. Он показывает, куда посмотреть, и не притворяется врачом.

Он также **не выдумывает данные**. Если бланк не распознался — так и написано. Референсы берутся только из самого бланка, не из справочников: они зависят от лаборатории, метода, возраста, пола и вида животного. Придуманное число в медицинской карте опаснее пропуска.

## Установка

Нужен macOS и Python 3.11+.

```bash
git clone git@github.com:JenZ19/healthtablo.git
cd healthtablo
./start.command
```

Скрипт сам создаст виртуальное окружение, поставит зависимости, заведёт базу и откроет браузер на `127.0.0.1:8765`. Дальше — двойной клик по `start.command`.

## Как пользоваться

1. Заведите членов семьи на странице профиля: имя, пол, дата рождения. Для животных — вид и порода. **Впишите все варианты написания имени**, какие встречаются в бланках: сопоставление документов идёт по ним.
2. Положите файлы в папку `inbox/` — PDF, фотографии, сканы.
3. Откройте «Входящие» и нажмите «Разобрать всё».
4. Что не распозналось — назначьте субъекта и дату руками там же.

```bash
python3 hub.py ingest --dry-run путь/к/бланку.pdf   # посмотреть разбор, не записывая
python3 hub.py stats                                # сколько документов и показателей
```

## Добавить свою лабораторию

Парсеры лежат в `hubcore/parsers/`, по файлу на лабораторию. Возьмите любой за образец — например `gemotest.py`.

```bash
python3 hub.py ingest --dry-run ваш_бланк.pdf
```

Команда покажет, что видит парсер. Дальше:

1. Создайте `hubcore/parsers/ваша_лаборатория.py` с методами `can_parse()` и `parse()`.
2. Впишите его в `PARSER_CHAIN` в `hubcore/parsers/__init__.py` — **перед** `GenericParser()`.
3. Добавьте тест в `tests/test_parsers.py`.

**Обязательно сверьте 5–10 значений с оригиналом бланка глазами.** Парсеры, написанные по предположениям о формате, врут почти всегда.

## Устройство

```
hub.py              CLI: init / ingest / serve / stats
hubcore/
  db.py             схема и миграции (sqlite3, без ORM)
  ingest.py         разбор входящих, сопоставление субъектов и маркеров
  ocr.py            распознавание сканов через macOS Vision
  analytes.py       справочник показателей, алиасы, единицы
  parsers/          по парсеру на лабораторию
  web.py            FastAPI + Jinja2
data/               ваша база и оригиналы документов (в git не попадают)
inbox/              сюда кладутся новые файлы
```

Полезное, если будете дорабатывать:

- **`layout_text()`** в `ingest.py` собирает текст PDF по координатам слов и восстанавливает колонки таблицы. Обычный `page.get_text()` превращает бланк в кашу — это ключевая функция всего разбора.
- **OCR тоже собирает колонки** из рамок Vision тем же способом, поэтому фотография бланка разбирается теми же парсерами, что и электронный файл.
- **Одноимённые показатели разводятся** по биоматериалу (кровь / моча), по форме записи (проценты / абсолютные числа) и по подвидам. Иначе на графике появляются несуществующие обвалы: 0,0 ммоль/л глюкозы мочи рядом с 4,7 крови читается как обвал сахара.

## Вынести на сервер

Готовые файлы служб systemd, скрипты выкатки и резервного копирования лежат в **[deploy/](deploy/)** — там же пошаговое описание с объяснением, почему приватная сеть лучше публичного адреса.

Хаб задуман домашним, но его можно поставить на свой сервер и открывать с телефона. Тогда обязателен вход:

```bash
python3 hub.py setpassword
```

Пароль спрашивается интерактивно — в историю командной оболочки он не попадает. Хранится только scrypt-хеш, в файле `data/auth.json` с правами 600; сам пароль не сохраняется нигде.

Без пароля хаб **откажется** слушать что-либо, кроме `127.0.0.1`:

```bash
python3 hub.py serve --host 0.0.0.0     # Отказ: вход не настроен
```

Это сделано намеренно. Самая частая ошибка при переезде — «сначала подниму, авторизацию добавлю потом», а в базе лежат ФИО, даты рождения и результаты анализов.

**Лучший способ доступа — не выставлять хаб в интернет вообще.** Приватная сеть вроде Tailscale или WireGuard даёт доступ с телефона откуда угодно, но не даёт публичного адреса: сканеры, которые находят открытые порты за сутки, до хаба просто не доходят. Домен и сертификат при этом не нужны — трафик уже зашифрован.

Если публичный адрес всё же нужен, ставьте перед хабом обратный прокси с HTTPS, а хаб держите на `127.0.0.1`. Тогда включите `HUB_TRUST_PROXY=1`, чтобы ограничение попыток входа считало реальные адреса, а не адрес прокси.

Куда класть данные отдельно от кода:

| Переменная | Что задаёт |
|---|---|
| `HUB_DATA_DIR` | база, оригиналы документов, превью |
| `HUB_INBOX_DIR` | папка, откуда забираются новые файлы |
| `HUB_TRUST_PROXY` | `1`, если впереди действительно стоит обратный прокси |

**OCR работает только на macOS** — он идёт через встроенный в систему Vision. На Linux-сервере PDF разбираются как обычно, а фотографии бумажных бланков — нет: хаб это замечает сам и просто пропускает распознавание.

## Демо

Посмотреть интерфейс на данных, не имея своих:

```bash
python3 demo_seed_husband.py            # залить вымышленный профиль

```
